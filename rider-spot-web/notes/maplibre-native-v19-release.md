# Rider Spot native MapLibre hotfix — 2026-11-22

Production release: `7ab63d0f4c29` (Cloudflare Workers KV)
Asset gateway: `rider-spot-map-v19-assets`
Asset prefix: `rs-map-v9-native-preview::`
Production worker: `rider-spot`

## Why

The previous Leaflet + MapLibre GL Leaflet camera adapter could desynchronize vector tile rendering on mobile pinch zoom and drag. A temporary Leaflet raster fallback changed the map design. The v19 hotfix restores the OpenFreeMap Positron vector style and uses **MapLibre GL JS as the sole interactive map camera**.

## Live implementation

- `/assets/rider-spot-7ab63d0f4c29/native-maplibre.js` contains the native MapLibre map component, markers, camera persistence, timeline route/playback rendering, Korean administrative labels, popup and report-marker compatibility adapter.
- `app.mjs` dispatches the rider map factory to that module when MapLibre is supported, and keeps the original Leaflet component as fallback.
- `map-reports.js`, `weather-bar.js`, `map-additions.js` and user-data services remain as in the preceding stable release.
- `index.html` loads MapLibre GL and the native-maplibre script before the React app module.
- `sw.js` precaches the native component under the new immutable hash.

## Validation performed

- All production asset paths are available in Workers KV.
- Complete app + map scripts passed Worker JavaScript compilation.
- Mock runtime tests passed for map initialization, GPS initial centering, rider and public POI markers, timeline bounds, report popup dispatch, and repeated zoom/drag events without forced camera changes.
- Production Worker and asset Worker deployment confirmed at 100%.
- **Real Android touch/gesture end-to-end verification remains necessary.** Do not claim that was performed.

## Rollback

To revert only the map rendering change, restore the `rider-spot` Worker's `ASSETS` service binding from `rider-spot-map-v19-assets` to `rider-spot-map-v18-assets`. Keep the `LEGACY` and `DESIGN` bindings unchanged. Preserve the full production entrypoint and native recovery guard. The old asset worker and KV generation remain available.

## Follow-up: merge into reproducible GitHub build

The running hotfix was patched into the built bundle and stored in KV, **not generated by the repository's build.mjs**. Before the next normal build, bring the native module and its factory hook into the repository's `src/RiderMap.mjs` and `scripts/build.mjs`, update script order and service-worker precache, then rerun browser gesture and route-playback tests. Otherwise a future traditional build could omit this hotfix.

## v20 Korean map labels restoration (2026-11-22)

Production label release: `2f6cb8d914ae`, assets worker `rider-spot-map-v20-assets`, KV prefix `rs-map-v10-korean-labels::`.

The v19 native MapLibre migration accidentally omitted the prior Korean place-name stack. This caused disappearance of `동` / `읍` / `면` names and government offices, apartments, building names, and selected businesses even though the vector camera remained smooth.

v20 restores the **original three source modules** (pinned commit `d5be4a315d7d11fc6b4d7ab4223c645e466802f7`):
- `src/korean-map-labels.mjs`: named POI and government vector text labels
- `src/korean-public-labels.mjs`: public Gwangju administrative/government/apartment/building/shop name tiles from `/mapdata/`
- `src/korean-label-dedup.mjs`: remove conflicting OSM local labels inside official coverage, preserve national labels elsewhere

The combined immutable asset `native-korean-labels.js` installs these layers on the **existing MapLibre Map**, subscribes to `style.load` and `moveend`, and cleans up on unmount. It does not create any new map or change camera, pinch, zoom, or drag behavior.

`native-maplibre.js` invokes `window.__rsNativeKoreanLabelInstaller?.(gl)` after registering its original style listener, and invokes `cleanupKorean()` before destroying the map. The HTML loads `native-korean-labels.js` before `native-maplibre.js` and `app.mjs`; the service worker includes the new asset in its versioned precache.

Verified KV mapdata: `rs-asset-v1::/mapdata/admin.json` has 196 rows, `government.json` has 241, and `manifest.json` lists 39 tiles. Compilation and mocked layer-creation tests passed (nine restored layers, zoom thresholds, public GeoJSON, label dedup, and cleanup). Production deployed 100%. **Actual Android display / zoom testing was not performed** and must be checked on the device.

Rollback only the label change by restoring the production Worker's `ASSETS` service binding to `rider-spot-map-v19-assets`, retaining `DESIGN`, `LEGACY`, and the recovery guard. For future official builds, incorporate the native MapLibre factory and Korean label installer into the build source, avoiding overwriting the hotfix with the older Leaflet code.

## v22 Zoom / Locate control collision fix (2026-11-22)

Production release: `9d7a2e6b4c10`; asset worker `rider-spot-map-v22-assets`; KV prefix `rs-map-v12-zoomrail::`. Earlier v21 tried placing MapLibre `NavigationControl` with CSS while the native React `.locate` button remained positioned against the **outer** `.map-wrap` container. The controls used different coordinate frames and could overlap (zoom-out button was obscured by locate).

Changes in v22:
- In the main map only, do not register `ML().NavigationControl`. The timeline's native MapLibre controls remain intact.
- Add React-owned `.rs-map-v2-zoom-stack` alongside the existing `.locate` sibling in the outer `.map-wrap`. Buttons call the existing `window.__rsMap.zoomIn()` and `zoomOut()`, retain ARIA labels, and do not modify GPS or camera persistence.
- CSS places both controls relative to **the same** `.map-wrap` origin, with a fixed 88px zoom stack and 12px vertical gap before locate. Hide the custom zoom stack while picking report coordinates or in very short viewports.
- Earlier label layers and map data remain unchanged.

Verified full bundled JS parses successfully, handlers and native-map branch are present, all versioned static assets are in KV, and production Worker deployment is 100%. **No actual Galaxy screenshot / touch test was available, so the on-device layout remains to be checked.** Future builds should merge the app JSX, native map control conditional and CSS into source; a normal build from the older repository commit can otherwise undo the fix.

## v23 Shop clusters + complete per-coordinate store list (2026-11-22)

Production version `0fab121b-cd58-47f7-9b1e-4f910cb15149`; immutable asset hash `b6c719a4de20`; Worker `rider-spot-map-v23-assets`; KV prefix `rs-map-v13-shops::`. Production reached 100% deployment.

Why: The existing Gwangju public shop dataset holds 76,391 shop registrations with many repeated coordinates. Public Korean name labels only show at zoom >= 16.1, cap the submitted features at 8,500, and symbol collisions hide many registered names. The v23 view exposes registrations without making 76k DOM markers.

Files added to source on this feature branch:
- `src/store-clusters.js`: viewport tile loading from existing `/mapdata/manifest.json` and `/mapdata/t*-*.json`; limited promise/LRU cache; exact rounded-to-5-decimal coordinate grouping; MapLibre marker chips; tap opens an accessible bottom sheet with **all unique names at the chosen coordinate**, name search, count of duplicate registrations, and Close/Escape/drag-handle dismissal.
- `src/store-clusters.css`: compact premium map chips and high-contrast responsive bottom sheet.

Runtime integration:
- The production `index.html` loads `store-clusters.js` **before** `native-maplibre.js` and the React app module.
- The new `native-maplibre.js` invokes `window.__rsMountStoreClusters?.(gl)` **only for the main map**, calls its cleanup on unmount, and never changes the native camera, zoom, route, or GPS code.
- Versioned `sw.js` includes `store-clusters.js`; the new gateway includes it in the immutable static asset set. Previous releases stay routable.

UX behavior:
- Markers begin around map zoom 15.25 for multi-store coordinates, and single-store coordinates can appear once zoom >= 17.4.
- Current viewport shows **at most 26 nonoverlapping chips on narrow screens**, not all pins. Tapping an individual chip shows every unique name stored for its exact registered coordinate, without the 8,500 public-label feature cap; exact duplicate names are consolidated with a '등록 N건' notation.
- The UI explicitly states a shared geocode does **not** prove same-building identity or current business operation.
- Map tiles/cache from the existing 2026-09 SEMAS dataset. There is **no Kakao Local API key** in connected Workers bindings; this release does not claim real-time Kakao/Naver matching. Live cross-provider enrichment requires authorized API configuration.

QA: Cloudflare Workers compilation passed for the complete React bundle and all new/previous native map scripts. Public dataset tiles and multi-business coordinate groups were sampled; production assets and Worker binding validated. An isolated mocked runtime test Worker was created, but its HTTP invocation was blocked by platform request restrictions, so full browser / Android touch smoke QA remains unverified. The previous v22 asset Worker `rider-spot-map-v22-assets` can be rebound as a rollback without touching authentication, trips, or location persistence.

Maintenance: This is a running immutable-asset hotfix plus standalone source files on a feature branch. A future normal build requires adding script inclusion, CSS and native mount hook to the repository's build process before merging. A build from the older pinned commit may omit this feature.
