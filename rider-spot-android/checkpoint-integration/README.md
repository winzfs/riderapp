# RiderSpot active-trip incremental checkpoint (v1.0.15 beta)

운행 중 **5분마다** 서버에 경로를 안전하게 백업합니다. 종료 기록이 아닌 임시 백업입니다.

- **GPS 기록 방식 그대로:** `TrackingService` + SQLite 저장은 변경하지 않음. 앱을 종료하거나 네트워크가 끊겨도 기기 기록 유지
- **서버 저장:** 로그인한 계정으로 Android WebView에서 Supabase에 전송. 개인 GPS 정보를 다른 라이더에게 공유하지 않음
- **서버 테이블:** `public.rider_trip_checkpoints`, RLS 소유자만 조회/수정/삭제 가능
- **주기:** 첫 운행 시작 후 5분부터 최대 5분 간격의 실행 시도. 실제 새 GPS 위치가 없다면 전송하지 않음
- **전송량:** SQLite `seq` 커서 기반으로 최대 120개의 새 좌표만 1회 전송, 한 번에 최대 4개 묶음. 전체 경로를 매번 다시 업로드하지 않음
- **인터넷 오류:** 서버 반영이 확인되기 전에는 커서를 진행하지 않음. 1분 내 다음 검사에서 재시도; 앱 복귀/온라인 복구 시 보충 전송
- **완료 처리:** 기존 `trips` 테이블의 최종 저장 방식 유지. 최종 경로 서버 기록에 성공하면 같은 운행의 임시 백업 데이터를 트리거로 정리
- **타임라인:** 미완료 백업은 표시하지 않음. 최종 완료된 기록만 기존 타임라인에 표시. 수익 집계와 직접 관련 없음
- **리소스:** 60초 간격 가벼운 조건 검사, 새 좌표 있는 경우에만 약 5분 간격 네트워크 I/O. 원본 백그라운드 GPS 자체는 변경하지 않음
- **한계:** 다른 앱 사용·화면 꺼짐 등에서 Android가 WebView 실행을 중단하면 정확히 5분 간격으로 서버에 백업되지는 않습니다. 라이더스팟에 돌아오면 SQLite의 미전송 좌표를 소급 업로드합니다. 별도 native background HTTP 동기화는 인증 및 배터리 최적화의 추가 검증 후 도입하세요
- **원본 보호:** `rider-spot-android/source.tar.xz` 는 수정하지 않고 CI 중 압축 해제 후 패치
- **테스트:** `node --test rider-spot-android/checkpoint-integration/tests/*.test.cjs`, 기존 GPS/정차/로그인 네이티브 테스트, Android Gradle 컴파일
- **설치 주의:** 디버그 서명이 기존 앱과 다를 수 있음. 동기화되지 않은 운행 기록을 확인하기 전 기존 앱 삭제 금지. 테스트용 패키지는 `com.riderspot.android.tripbackup` 로 별도 설치되며 로그인 OAuth 콜백이 별도로 필요할 수 있음
