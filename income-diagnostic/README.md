# 라이더스팟 수익 인식 진단 APK (개발자 전용)

기존 라이더스팟 APK의 패키지명/데이터/서버/수익 원장을 건드리지 않는 독립 설치형 테스트 도구입니다.

## 무엇을 검사하나
- 쿠팡이츠 배달파트너 com.coupang.mobile.eats.courier, 배민커넥트 com.woowahan.bros 의 접근성 이벤트
- 화면 전환 및 텍스트 변경 이벤트 횟수 / 실제 분석 횟수 (850ms 이상 간격)
- 접근성 텍스트를 읽을 수 있었는지, 트리 접근 실패 횟수
- 배달 완료 문구/원 표시 금액 탐지, 단일 금액 후보 수·합계, 애매한 화면과 중복 억제 수
- 측정 세션 중 앱 프로세스 누적 CPU 실행 시간, 순간 PSS 메모리
- 전체 휴대폰의 시작/종료 배터리 잔량 변화
- 사용자가 직접 입력한 실제 완료 건수·총액과 후보 수·총액 비교

## 사용
1. APK를 설치합니다. 본 앱과 패키지명이 다르므로 함께 설치됩니다.
2. 접근성 설정에서 '라이더스팟 수익 인식 테스트'를 켭니다. 보안 경고가 나오면 목적을 확인한 후 선택합니다.
3. 측정 시작을 탭하고 평소대로 쿠팡이츠/배민에서 배달합니다. 화면 캡처는 필요 없습니다.
4. 테스트를 마치면 측정 종료. 실제 배달 건수와 금액을 입력해 차이를 확인하고 보고서 공유를 누릅니다.
5. 보고서 공유시에도 화면 텍스트, 고객 주소 및 이름, 위치 정보는 수집/전송되지 않습니다.

## 주의
- 자동 감지 기록은 실제 배달건이 아니라 '후보'입니다. 화면 구조를 모르는 상태에서 완료 문구+단일 금액으로 판단하므로 누락/오인식이 가능합니다. 현재의 건수 후보 비율은 진정한 precision/recall이 아닙니다.
- 실제 인식률 검증에는 개별 배달 완료 시점과 금액을 짝지은 정답 기록이 필요합니다. v0.2은 총건수/총액 비교로 1차 타당성만 측정합니다.
- 원본 접근성 문자열과 화면 캡처/OCR 결과는 디스크에 저장하지 않습니다. 이벤트에 포함된 문자열은 메모리에서만 검사하고, 기기에는 금액 후보·플랫폼·상태·시각·카운터를 최대 120개 보관합니다.
- 인터넷 권한, 위치 권한, 알림 접근 권한, 오버레이 권한 없음. 접근성 서비스가 활성화되어도 측정 시작한 세션에서만 텍스트 파싱을 수행합니다.
- CPU 실행 시간은 앱 프로세스 전체 기준으로 UI를 열어둔 비용을 포함합니다. 배터리 잔량 변화는 휴대폰 전체 소비량이므로 측정만으로 앱 전력 소모량을 단정할 수 없습니다. 이후 앱을 켠 조건/끄고 운행하는 조건을 비교하세요.
- 접근성 서비스가 앱 업데이트/OS 정책으로 중단되면 기록이 누락될 수 있습니다.
- Android 13+ 환경에서 사이드로드 앱의 접근성이 차단되면 기기 보안 정책에서 앱별 '제한된 설정 허용'이 필요한 경우가 있습니다. 보호 기능을 해제하기 전 위험과 권한 범위를 확인하세요.

## 개발/빌드
JDK 17, Android SDK 35, Gradle 8.10.2, Android Gradle Plugin 8.7.3.
cd income-diagnostic && gradle :app:assembleDebug
GitHub Actions 'RiderSpot Income Recognition Diagnostic APK' 가 push 때 빌드 및 검증 후 별도 pre-release로 배포합니다.

> 테스트 목적이며 쿠팡/배민의 내부 API를 호출하거나 결제/정산 정보를 직접 가져오지 않습니다.

## v0.2 변경
- 개인정보 원문 대신 화면별 금액 후보 및 분류 라벨만 기록합니다.
- 단일 금액이라는 이유만으로 배달료로 인식하지 않습니다. 배달료 문구가 주변에 있을 때만 후보 집계합니다.
- 합계·미션 의심 금액을 별도로 표시하고 화면 검사 최소 간격을 350ms로 조정했습니다.
- 0.1과 별도 앱으로 설치됩니다 (com.riderspot.incomediag.v02). 중복 감시를 방지하기 위해 이전 버전의 접근성 서비스를 끄세요.
- 화면 후보 탐지는 실제 배달 건수나 정산 금액의 정확도를 증명하지 않습니다.
